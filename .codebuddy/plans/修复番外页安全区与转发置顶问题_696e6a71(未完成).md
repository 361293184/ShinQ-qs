## 用户需求
宝宝要优化番外功能的两个问题：

1. **番外页面太靠顶端**：私聊里的番外生成页打开后，以及生成结果预览后，内容都太靠顶端，希望整体往下移。
2. **转发给角色后页面未置顶**：在拾光里点击「转发给角色」并选择角色后，界面不切换（停在拾光/无反应），但按返回回到上一级再重新进入就能看到 Chat 和那条转发的消息。说明 activeApp 已切到 Chat 但界面未即时刷新。

## 产品概述
这是 SullyOS（React + TypeScript 桌面 AI 陪伴 App）的番外功能优化。番外生成页是私聊入口弹出的全屏独立页面（非悬浮窗），生成的小说可收藏到「拾光」App，并从拾光转发给角色（写角色记忆 + 注入私聊消息 + 跳转私聊）。

## 核心功能
- 番外生成页顶栏正常让位安全区与状态栏，内容不再怼顶。
- 从拾光转发给角色后，立即切到 Chat 并显示对应角色会话与转发消息。


## 技术栈
- React + TypeScript + Tailwind CSS（SullyOS 现有技术栈，无新增依赖）
- CSS 变量安全区约定：`--chrome-top`（= `calc(var(--safe-top) + 1.5rem)`，index.html:132）、`--safe-bottom`

## 实现方案
### Bug 1：番外页顶栏怼顶
- 根因：`FanwaiGeneratePage.tsx` 两处（主页面 header 153 行、生成预览层 header 358 行）用了嵌套三层的 `style={{ paddingTop: 'max(0.5rem, var(--chrome-top, env(safe-area-inset-top, 0px)))' }}`。该表达式在部分手机 WebView/低版本浏览器 computed-value 阶段解析失败 → 内联样式被丢弃 → 回落到 Tailwind 类 `pt-2`(0.5rem)，导致内容怼顶。
- 修复：改为全库统一的 `style={{ paddingTop: 'var(--chrome-top)' }}`（与 FanwaiApp:99/153、NovelApp、JournalApp、VRWorldApp 一致）。同时为满足用户「整体往下移」的观感，按 DreamTheater:538 的成熟先例追加一点余量：`paddingTop: 'calc(var(--chrome-top) + 0.25rem)'`。
- 不移除 Tailwind 的 `pt-2`，因为内联 style 优先级高于 class，内联生效时覆盖 `pt-2`，解析失败时回落 `pt-2` 作为兜底（不会怼到 0）。

### Bug 2：转发后 Chat 未置顶
- 根因：`FanwaiApp.tsx` 的 `handleForward` 里 `await DB.saveMessage(...)`（IndexedDB 异步写，失败会 reject）放在导航 setState（`setForwardTarget/setDetail/setActiveCharacterId/openApp`）之前，把「切到 Chat」完全阻塞。DB 慢或失败时导航逻辑不执行，界面停在拾光，转发弹层（z-[90]）仍挂载。
- 修复：把导航相关 setState（`setForwardTarget(null)`、`setDetail(null)`、`setActiveCharacterId(role.id)`、`openApp(AppID.Chat)`、`addToast`）**提前到 `await DB.saveMessage` 之前**，让它们在同一 React 批次内同步提交，Chat 挂载时即可拿到正确的 `activeCharacterId`（对应 Chat.tsx:232 的 char 查找与消息加载）。DB 写改为后台进行，用 `.catch` 兜底失败提示。这与全库成功先例（OSContext.tsx:1917-1918、1798-1799、4918-4921）一致——都是同步导航、无 await 拦截。

## 实现要点
- **不改** PhoneShell、OSContext、index.html，保持 SullyOS 安全区单一来源约定。
- 修复 Bug1 时统一两处 header 写法，避免遗漏。
- Bug2 将 `DB.saveMessage` 改为不阻塞导航的后台写，用 `.catch(() => addToast('转发内容保存失败', 'error'))` 兜底，不影响「已转发」成功提示。
- 两处改动均为小范围、低风险，不影响其它功能。
