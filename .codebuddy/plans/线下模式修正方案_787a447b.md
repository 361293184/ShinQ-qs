## 需求概述

修复用户实测「线下模式」发现的 4 个问题（commit be927ed 已实现，需调整）：

1. **点「线下」入口行为**：目前点 tile 直接开关并弹「线下已开」toast。应改为：点「线下」弹出「线下设置」弹窗，用户在弹窗第一项开关处自己开/关，开关即生效。
2. **开场旁白**：目前开启线下时，用户侧自动发出一条「（你轻轻走进…）」的 user 气泡，错误。应改为：进入线下时由**角色自动生成一轮开场旁白**（assistant 旁白消息，无用户气泡）。
3. **长分隔线**：目前缺少方案要求的「进入/退出」长分隔线。开启时在消息流末尾插「进入分隔线」，关闭时插「退出分隔线」。
4. **输入模式悬浮球**：目前是输入框上方一整栏 chip。应改为**输入框外侧右侧（紧贴发送按钮左侧）的小圆球**（用户已确认选 B）。

已确认决定：
- 悬浮球位置：输入框外侧右边、紧贴发送按钮左侧，做成小圆球。
- 开场旁白：默认由角色生成（assistant 旁白，不进用户气泡）。

## 技术方案

### 核心改动逻辑

**入口重定向到设置弹窗**：`handlePanelAction` 的 `offline-toggle` 与 `offline-settings` 两个 case 统一改为只 `setOfflineSettingsOpen(true)` + `setShowPanel('none')`，不再直接 toggle / toast / 发消息。开关动作收敛到弹窗内。

**开关动作收敛**：`OfflineSettingsModal` 的 `onChange` 中，当 `next.enabled !== undefined` 时，调用 Chat.tsx 新增的 `handleOfflineToggle(next.enabled)`：
- 开启：插入「进入分隔线」system 消息（`metadata:{offlineDivider:'start'}`）→ `reloadMessages` → 若开场旁白开关开则触发角色开场旁白。
- 关闭：插入「退出分隔线」system 消息（`metadata:{offlineDivider:'end'}`）→ 重置输入模式为 dialogue → `reloadMessages`。

**开场旁白正确做法**：不调 `handleSendText`（会落用户气泡）。参照 proactive 模式存一条隐藏 user 消息 `metadata:{proactiveHint:true, hidden:true}`（content=buildOfflineOpeningRequest，作为 AI 上下文），再 `triggerAI(messages)` 触发。Chat.tsx displayMessages 第 3169 行已过滤 `proactiveHint`，不显示用户气泡。assistant 回复由 `applyAssistantPostProcessing` 自动落库并自动带 `offline:true`，走旁白渲染（`buildOfflineOpeningRequest` 明确要求只写旁白不加引号，全部解析为 narration 居中斜体）。

**长分隔线渲染**：新增 `Message.metadata.offlineDivider`（'start'|'end'）约定。MessageItem 在第 3730-3731 行「空内容跳过守卫」之后优先判断该标记，返回横跨整宽的细线 + 居中「线下模式 · 进入/结束」小字，避免落到 system 胶囊条渲染分支。

**输入悬浮球**：移除 ChatInputArea 输入栏上方整栏 chip，在发送按钮左侧渲染小圆球按钮（FilmScript 图标，dialogue/narration 用颜色区分），点击切换；textarea placeholder 联动当前模式。

### 关键约束
- 开场旁白必须走 triggerAI，不用 handleSendText。
- 分隔线消息 role='system'，MessageItem 需在 isSystem 胶囊条分支之前优先处理 offlineDivider。
- 开/关线下后重置 offlineInputMode 为 'dialogue'。
