## 需求概述

实现消息撤回功能，让对话中「说错话可以后悔」。

## 核心需求

1. **双向撤回**：用户撤回自己发的消息；角色主动撤回自己发的消息。
2. **2 分钟时效**：消息发出 2 分钟内可撤回，超时撤回入口消失/置灰（用户和角色都受此限制）。
3. **角色会后悔**：角色说错话会通过工具自主撤回自己刚说的消息（基本都是现场撤回）。
4. **非物理删除**：撤回不是物理删除，而是把 content 替换为撤回提示 + 打 `isRevoked` 标记，保留对话时间线。
5. **AI 上下文过滤**：组装发给 LLM 的消息数组时过滤掉撤回消息，避免 AI 把「已撤回」当真实内容理解。

## 撤回文案
- 用户撤自己：「你撤回了一条消息」
- 角色撤自己：「{角色名} 撤回了一条消息」

## 边界
- 撤回入口仅对 2 分钟内的消息开放，超时隐藏/置灰。
- 撤回后 UI 气泡显示撤回提示（不显示原文），灰色小字样式。

## 技术栈
- React + TypeScript（现有项目，沿用现有架构）
- IndexedDB 持久化（utils/db.ts 现有模式）
- 角色工具调用框架（amsg2ToolBridge / OpenAI tools 机制，现有）

## 实现方案

撤回采用「替换 content + 打标记」而非物理删除，保留对话时间线。数据流：UI/工具层调用 DB 更新单条消息 → 触发 IndexedDB 事件刷新 → MessageItem 按 isRevoked 渲染撤回提示 → AI 上下文组装时过滤 isRevoked。

### 关键决策
- **DB 新增 `recallMessage(id, newContent)`**：因现有 `updateMessage`（只改 content）和 `updateMessageMetadata`（只改 metadata）不能一次改两个字段，新增一个方法用单事务同时写 content + metadata.isRevoked，避免两次写入的原子性问题。
- **AI 过滤集中一处**：在 `buildMessageHistory`（chatPrompts.ts:1109）的 `effectiveHistory` 过滤处加 `isRevoked` 过滤，所有 AI 调用方（私聊/主动消息/彼方/家园/情绪评估）一网打尽。
- **角色主动撤回复用工具框架**：新增 `revoke_own_message` 工具，走现有 `executeAmsg2Tool` 分发。角色上下文需暴露「最近自己发的消息带本地 id」供其指认撤回。
- **2 分钟时效**：用户侧在长按菜单条件渲染（超时隐藏「撤回」）；角色侧在工具 handler 里校验时间，超时返回失败。

### 性能与可靠性
- 单条消息更新走 IndexedDB 自增 id 精确定位，无全表扫描。
- `isRevoked` 过滤为 O(n) 单次遍历，叠加在现有过滤链上，无额外开销。
- 撤回后 fire `messages-updated` 事件刷新 UI（沿用现有 saveMessage 触发机制）。

### 数据流
长按消息 → 撤回 handler / 角色工具 → DB.recallMessage（改 content + isRevoked）→ fire 事件 → UI 刷新（显示撤回提示）→ AI 上下文过滤 isRevoked

### 模块划分
- **类型层**：Message 加 isRevoked
- **数据层**：DB.recallMessage
- **UI 层**：长按菜单「撤回」入口 + MessageItem 撤回样式
- **AI 层**：buildMessageHistory 过滤
- **角色自主层**：revoke_own_message 工具 + 上下文暴露消息 id

## 实现注意
- Message.id 是 number（本地 IndexedDB 自增 id），工具参数 message_id 用它，非远端 messageId。
- 角色撤回校验 2 分钟时效，超时工具返回明确失败信息。
- 撤回文案区分用户/角色视角。
- 不要物理删除，保留时间线。
- 兼容旧数据：isRevoked 为可选字段，未设置视为未撤回。
