## 需求概述
用户在**生成页**的纯文字番外预览末尾找不到续写入口。用户明确：续写功能不是只在"检测到截断"时才出现，而是**每篇纯文字番外都要常态拥有**——入口无条件常驻在纯文字番外正文末尾，随时可点开续写。

## 核心功能
- **生成页纯文字番外预览末尾常态显示「✍️ 续写」入口**（不管是否截断，只要生成了纯文字就显示）
- 点开续写弹框，可填**续写走向**（可选，限 100 字，留空默认接前文自然写）
- 点击开始 → AI 接续生成 → 内容**追加进预览正文末尾**，像一篇完整小说
- 可**反复续写**（续写完成后入口仍在）
- 续写中状态（入口变「✍️ 续写中…」禁用，防连点）
- 失败提示「续写失败，重试？」；副 API 未配置提示
- **续写后的完整内容随收藏保存**
- 拾光收藏详情页已有的续写功能保留不动

## 边界
- 仅纯文字番外（generatedFormat !== 'html'）；HTML 番外不显示续写（标签断点难续写）
- 续写用副 API（与生成同通道）
- 不动其他流程、记忆系统


## 技术栈
沿用现有 React + TypeScript 架构。改动集中在生成页 `components/fanwai/FanwaiGeneratePage.tsx`，复用已有的 `continueFanwai`（utils/fanwaiGenerator.ts）和拾光详情页（FanwaiApp.tsx）已验证的续写模式。

## 实现方案
核心：在生成页纯文字预览末尾加续写入口 + 弹框 + handleContinue，复用已有的 `continueFanwai(char, story, subApi, direction)` 副 API 续写函数，成功后将新内容追加到 `generated` state，收藏时自然保存完整内容。

### 关键决策
1. **复用 continueFanwai**：不新写续写逻辑，直接调 utils/fanwaiGenerator 里已有的 `continueFanwai`。它内部用 `buildContinueFanwaiPrompt`（原文末尾 2000 字 + 人物/视角/世界观 + 走向）走副 API，返回续写片段。
2. **构造临时 FanwaiStory 传参**：`continueFanwai` 需要 `story.content` 作为原文。生成页没有完整的 FanwaiStory 对象，需构造一个临时对象：`{ id: 'fanwai-continue-...', charId, charName, style, wordCount, pov, worldSetting, content: generated }`（只读 content/pov/worldSetting，字段够用即可）。
3. **追加到 generated**：成功后 `setGenerated(prev => prev + '\n\n' + res.content)`。生成页的 `title`/`body` 由 `generated` 首行 split 提取，追加末尾不影响标题；`handleCollect` 收藏的是当前 `generated`，续写后收藏自动含完整内容。
4. **常态显示入口**：续写入口在纯文字分支（`generatedFormat !== 'html'`）无条件渲染（只要 `generated` 非空），不判断截断——满足"每次都要有"。
5. **弹框样式**：仿拾光详情页续写弹框（米白卡片 + 走向 textarea 限 100 字 + 开始/取消），适配生成页现有卡片风格。

### 性能与可靠性
- 续写为副 API 一次调用，无额外前端开销
- continuing state 防连点；失败 catch 提示，不破坏生成页状态
- 不改动文字番外/HTML 番外的既有生成流程
