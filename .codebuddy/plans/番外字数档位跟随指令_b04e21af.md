## 用户需求
番外的生成指令里总是会带明确的数量要求（生成多少字、多少层楼、多少条对话等），例如「论坛不少于80层楼」。用户希望**字数档位默认跟随指令**：当指令里有明确的字数/楼层/对话条数等数量要求时，以指令为准，而不是被页面上选择的字数档位强制覆盖。指令没有明确数量要求时，才用页面字数档位作为兜底。

## 核心功能
- 检测指令（worldSetting）里是否含明确的数量要求（字数/楼层/对话条数/回复数等）
- 指令有明确数量 → 生成 prompt 里以指令为准，页面字数档位让位（仅作兜底、不作为硬约束）
- 指令无明确数量 → 保持现状（以页面档位为准）
- 文字番外和 HTML 番外（如论坛体「80层楼」）都生效
- 生成页字数区在指令含数量要求时给出提示

## 技术栈
沿用现有 React + TypeScript 项目架构，改动集中在番外生成链路（`utils/fanwaiGenerator.ts`）、格式检测模块（`utils/fanwai/formatDetector.ts`）、生成页（`components/fanwai/FanwaiGeneratePage.tsx`）。

## 实现方案
核心思路：新增一个纯函数检测指令里是否有明确的数量要求，据此动态决定 `wordsLine`（prompt 里的篇幅指令）是「以指令为准」还是「以页面档位为准」。文字与 HTML 番外共用同一条 `wordsLine`，一处改动两端生效。

### 关键决策
- **检测函数位置**：放 `utils/fanwai/formatDetector.ts`（该目录已存在，与格式识别集中管理），导出 `detectExplicitQuantity(worldSetting?): boolean`。逻辑：匹配「数量限定词（不少于/不低于/至少/以上/以下/大于/超过/≥/≤ 等）+ 量词（字/层/楼/条/段/句/对话/回复 等）+ 数字」模式。
- **wordsLine 改造**：在 `buildFanwaiPrompt` 内计算 `hasExplicitQuantity`。为 true 时，`wordsLine` 文案改为「严格按指令里要求的字数/楼层/对话条数完整生成，页面字数档位仅供参考、不作为硬约束；宁可有头有尾地写完，不要省略」；为 false 时保持现有「以本页选的字数为准」。
- **作用范围**：`wordsLine`（line 454-456）在常规模式 prompt 的 line 490 注入，HTML 番外共用同一 prompt，故文字/HTML 同时生效，无需分开处理。
- **生成页提示**：字数档位区（line 249 起）在 `detectExplicitQuantity(worldSetting)` 为 true 时显示一行小提示「检测到指令有字数/条数要求，将以此为准」，与现有 HTML 格式检测提示风格一致。

### 性能与可靠性
- 检测函数为纯字符串正则匹配，O(长度) 单次调用，无性能开销
- 不改动 max_tokens（已取消上限）；不动其他番外流程
- 保持向后兼容：指令无明确数量时行为完全不变
