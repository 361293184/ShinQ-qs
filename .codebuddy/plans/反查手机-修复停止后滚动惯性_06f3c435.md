## 需求
修复反查手机接管功能的一个体验 bug：用户手动点「结束查看」胶囊（X）后，胶囊消失，但屏幕仍会继续滚动一小段，看起来像"角色还在控制屏幕滑动"。

用户确认这是一个需要先处理的简单问题（逐个处理反查手机问题，从简单的开始），暂不改动其他反查手机问题。

## 功能目标
- 用户点胶囊 X 结束接管后，屏幕滚动**立即停止**，不再有任何惯性滑动。
- 正常结束（计划走完）时同样生效。
- 不改变接管功能的其他行为，不触碰 Message 相关文件。

## 非目标
- 不处理"滑到谁读谁"的聊天显示脱节（问题2）。
- 不处理"角色盲点、app 内部真实操作"（问题3）。
- 不改任何 Message 文件（工作区未提交的 types.ts / apps/Appearance.tsx / components/chat/ChatList.tsx 保持不动）。

## 技术方案

### 根因
`utils/checkPhone/reverseTakeoverRunner.ts` 中：
- `simulateScrollInApp()`（84-95 行）每次调用 `scroller.scrollTo({ top: ..., behavior: 'smooth' })`。`behavior:'smooth'` 是浏览器异步执行的平滑滚动动画，发出后由浏览器内部继续滚完。
- `stopScrollLoop()`（105-110 行）只 `clearInterval(current.scrollTimer)` 清定时器，**没有打断已发出的 smooth 滚动动画**。
- 因此点结束胶囊（`PhoneShell.tsx:979` → `stopTakeoverRunner` → `finalizeRunner` → `stopScrollLoop`）后，interval 停了，但已发出的 smooth 动画仍由浏览器继续执行，屏幕多滚一小段。

### 修复策略
在 `stopScrollLoop()` 清 interval 后，用同文件已有的 `findScroller()`（71 行）取当前活跃 App 的可滚动容器，对其执行一次 `scrollTo({ top: scroller.scrollTop, behavior: 'auto' })`——停在当前位置，但会**立即取消进行中的 smooth 滚动动画**。

关键点：
- 用 `behavior: 'auto'` 而非 `'instant'`：部分 TS lib 的 `ScrollToOptions.behavior` 类型无 `'instant'`，用 `'auto'` 最兼容。
- `top` 取当前 `scrollTop`：不改变位置，只中断动画，避免视觉跳动。
- 若 `findScroller()` 返回 null（无可滚动容器），静默跳过，不影响停止逻辑。
- 该函数同步执行，无需 async；若所在作用域允许，可将 `findScroller()` 调用放入 `stopScrollLoop` 内（两者同模块可直接访问）。

### 性能与可靠性
- 改动仅一处函数，无新增依赖、无状态变化、无性能开销。
- `finalizeRunner`（183-233 行）对 `interrupted`（用户点结束）和正常结束都会调用 `stopScrollLoop()`，两种场景都被覆盖。
- 不触碰 Message 文件，避免把反查手机修复混入 Message 未提交改动。

### 不引入新模式
沿用模块内已有的 `findScroller()` 工具函数，不新增全局/外部依赖，符合当前代码风格。
