# 微信桥 · 从零开始的部署手册

这份手册是写给**第一次装微信桥的人**的：照着点完，你就能在微信里跟角色聊天，回复和 App 里是同一套上下文。

全程只需一个浏览器，**不用装任何软件、不用敲命令**。第一次装大约 10~15 分钟，装完以后就再也不用管它了。

> 微信桥是 SullyOS 的一个可选用功能：把**你自己的一个微信号**接进来，让角色住在里面——
> 你在微信里发消息，角色用**和 App 里完全相同的上下文**回你，一来一回也会回流进 App 的聊天记录。
> 用的是微信官方的 iLink Bot 接口（2026 年随 ClawBot 开放），扫码登录、官方接口，基本没有封号问题。

---

## 一、先弄明白：为什么需要一个"后端"

**因为 App 关掉之后，得有个东西还醒着。**

微信的消息靠"长轮询"接收——要一直有个程序挂在云端等着收消息、顺手把回复发回微信。你的手机/电脑一关就不行了，所以这个"醒着的东西"必须放在一台**一直开机的服务器**上。

微信桥的做法是：把它放在**你自己的 Cloudflare 账号**里（免费，一个人用完全在免费额度内）。

| | 谁来出这台服务器 | 你的微信登录态放在谁手里 |
|---|---|---|
| **SullyOS 微信桥（本文档）** | 你自己的 Cloudflare 账号 | **你自己**（别人拿不到） |
| 那类"扫码就能用"的第三方平台 | 平台方 | **平台方**（技术上他们能读你的聊天、能代替你发消息） |

说白了：**"扫码就能用"不是不需要服务器，而是服务器在别人家。** 这份手册多花的十来分钟，换的是"你的微信登录态和聊天内容不经过任何第三个人"。

> 顺带说清楚：**服务器为了替你调模型、替你发微信，必须能解出你的密钥**（否则它没法干活）。
> 区别只在这台服务器是谁的——这里是你自己的。

## 二、装之前先准备两样

### 1. 一个 Cloudflare 账号（免费）

没有就注册一个：<https://dash.cloudflare.com/sign-up>，邮箱 + 密码即可，**不用绑卡**。

### 2. 一份微信桥后端代码

**最省事的办法：找把这份教程发给你的人，要一个叫 `wechat-bridge-worker.bundle.js` 的文件**
（微信、邮箱发文件都行，大约 50 KB）。拿到后用**记事本**打开它 → **Ctrl+A 全选 → Ctrl+C 复制**，先放着。

> 为什么推荐要文件而不是点链接：这个文件平时放在 GitHub 上

> 但国内直连 GitHub 时常常打不开。链接能打开就点链接（浏览器里会显示一大段代码，全选复制即可），

复制到的这段代码**先别急着粘贴**，第 2 步会告诉你什么时候用。

## 三、开始装（路线一 · 面板点击，推荐）

### 第 1 步 · 新建一个 Worker

1. 登录 Cloudflare → 左侧点 **Compute (Workers)**（也可能写成 **Workers & Pages**）
2. 右上角 **Create** / **创建** → 选 **Workers** → **Start with Hello World!** / **从 Hello World 开始**
3. 名字填 `sullyos-wechat-bridge`（记住这个名字，最后地址会用到），点 **Deploy**

**你应该看到：** 进入一个概览页，右上角有一个 `https://sullyos-wechat-bridge.你的子域名.workers.dev` 地址。

> 如果它提示你还没有 `workers.dev` 子域名，会让你起一个名字（比如你的昵称拼音），起好继续就行——这个名字会出现在最终地址里。

### 第 2 步 · 把后端代码贴进去

1. 在这个 Worker 页面点 **Edit code** / **编辑代码**（右上角）
2. 在编辑器里按 **Ctrl+A 全选 → Delete 删掉**（把自带的 Hello World 示例清空）
3. 回到第 2 步准备好的那个代码页面：**Ctrl+A 全选 → Ctrl+C 复制**，粘进编辑器
4. 右上角 **Deploy** / **部署**，确认覆盖

**你应该看到：** 顶部提示部署成功（Deployed / 已部署），版本号是新的。

> 代码里第一行有注释 `generated by scripts/build-workers.mjs`，认准它就不会贴错。

### 第 3 步 · 建一个数据库

1. 左侧点 **Storage & databases** / **存储和数据库** → **D1 SQLite Database** → **Create Database** / **创建数据库**
2. 名字填 `sullyos-wechat-bridge`，点创建

**你应该看到：** 进入这个数据库的详情页，里面有一串 **Database ID**（一串 uuid，形如 `cb7e97ae-d1d7-...`）。**先不用复制它**，下一步在面板里直接选就行。

> 表结构不用管，也不用去它的控制台粘 SQL——回到 App 里点一个按钮就会自动建好（第四步）。

### 第 4 步 · 把这个数据库绑给 Worker

1. 回到你的 Worker 页面 → **Settings** / **设置** → 找 **Bindings** / **绑定**（有的面板写作 **Variables and Bindings**）
2. **Add binding** / **添加绑定** → 类型选 **D1 database** / **D1 数据库**
3. **Variable name 必须填 `DB`**（一定是两个大写字母 D、B，填错后端会全线报错）
4. Database 下拉里选中刚建的 `sullyos-wechat-bridge` → 保存

**你应该看到：** 绑定列表里多出一条 `DB → sullyos-wechat-bridge(D1)`。

### 第 5 步 · 加一个"每分钟看一眼"的定时器

1. 同一个 Worker 页面 → **Settings** / **设置** → **Trigger events** / **触发器**（有的面板写作 **Cron Triggers**）
2. **Add Cron Trigger** / **添加 Cron 触发器** → 表达式填：

```
* * * * *
```

（五个星号，意思是"每分钟一次"。**这行是微信消息唯一的入口**，没有它你在微信里发消息不会有人回。）

**你应该看到：** 触发器列表里出现 `* * * * *`。

### 第 6 步 · 填两把钥匙

1. Worker 页面 → **Settings** / **设置** → **Variables and Secrets** / **变量和密钥** → **+ Add** / **添加**
2. 加第一条：
   - 类型：**Secret**（⚠️ **一定要选 Secret，不要选 Text**，原因见下面）
   - 名字：`MASTER_KEY`
   - 值：**一串又长又乱的字符**，至少 32 位，字母数字混着来，比如键盘上乱敲一段：
     `Kf7pQ2mZx9Rt4Lw8Vb3Nd6Yh1Sc5Ja0Qw`
   - **把这串存到你的密码管理器/备忘录里**——它换掉之后，之前存的微信登录态和模型凭据就都解不开了。
3. 再加第二条：
   - 类型：**Secret**
   - 名字：`WX_BRIDGE_TOKEN`
   - 值：**再乱敲一串**（同样存好，一会儿要填进 App）
   - 作用：给后端的接口上一把锁——**不填的话，任何知道你地址的人都能读走你的消息、删掉你的绑定、覆盖你的模型凭据**。强烈建议填。

**你应该看到：** 列表里有两条 **Secret** 类型的变量，各带一个"值已隐藏"的标记。

> ⚠️ **为什么类型必须是 Secret**：如果存成 Text（明文变量），Cloudflare 下一次部署 Worker 时会把明文变量清空，
> 后端会立刻全线不可用（App 里显示"连不上"或"没法解密"），而且你重新敲一串新的，之前加密存进去的东西就再也解不开了。

### 第 7 步 · 先验一下后端活着没

在浏览器里打开（把地址换成你自己的）：

```
https://sullyos-wechat-bridge.你的子域名.workers.dev/health
```

**你应该看到：**

```json
{"ok":true,"service":"wechat-bridge","version":"0.2.0"}
```

看到它，说明后端已经跑起来了。看不到的去 Cloudflare 的 **Deployments** 看部署有没有成功。

## 四、把功能打开（回到 SullyOS，四步）

打开 SullyOS → **神经链接** → 点开你要让微信扮演的那个角色 → **「设定」页签** → 找到 **微信桥** → 展开它。

### 1 · 连上后端并建表

1. 展开 **连接配置（所有角色共用）**
2. **微信桥 Worker 地址**：填第 7 步那个 `https://...workers.dev` 地址（**结尾不要带斜杠**）
3. **Worker 密钥（WX_BRIDGE_TOKEN）**：填第 6 步那第二串乱码
4. 点 **检查连接**

**你应该看到：**
- 提示"连接正常，正在收微信消息"
- 下面那一行数据表状态：如果是**琥珀色「云端数据表还没初始化」**，点它右边的 **初始化数据表** → 变成**绿色「云端数据表已就绪（5 张）」**

> 这一步就是替代"去数据库控制台粘 SQL"的按钮。它做的是建 5 张表，重复点也没事。
> 如果你连的是老早就装好的后端，这里应该本来就是绿的。

### 2 · 保存模型凭据

在 **LLM 凭据** 那三格里填上你要用的模型接口（API 地址 / API Key / 模型名）。

- 懒人做法：如果 App 里已经配好了聊天 API，点 **一键填入当前聊天 API**，三格自动填好
- 然后点 **保存凭据**

**你应该看到：** 提示"LLM 凭据已加密保存到 Worker"。

> 这个凭据只存在你自己后端的数据库里、用你第 6 步那把 `MASTER_KEY` 加密。
> 云端靠它生成回复——所以**关掉 App 也能回你**。模型的钱花的是你自己的 key，不经过任何人。

### 3 · 上传角色上下文

点 **上传角色上下文**。

**你应该看到：** 提示"已上传模板；角色上下文已上传（N 条消息）"。

> 这一步把角色的设定、世界书、记忆、聊天记录打包传到云端，微信里的回复就靠它——**这也是"不会 OOC"的根本原因**：
> 云端用的不是另一套提示词，而是 App 里那份原样的上下文。
>
> 以后不用反复点：你在 App 里聊过之后，云端会自动跟上（每角色至少间隔 5 分钟）。

### 4 · 扫码登录微信

点 **扫码登录（绑定为「角色名」）** → 用**你要接进来的那个微信号**扫二维码 → 手机上确认。

**你应该看到：** 提示"微信登录成功，已绑定到「角色名」"，卡片上出现"这个微信正在扮演「角色名」"和「最近轮询：时间」。

> 建议用**小号**。这个微信号里收到的消息都会交给这个角色处理，别把主号接进来。
>
> 换角色不用重扫：去那个角色的设定页点「改绑到当前角色」。
> 重新扫码也没关系：**旧的绑定会被自动清理**，永远只留最新那一条。

## 五、装好了没有？五步自检

按顺序都对，就是装好了：

| # | 检查什么 | 应该看到 |
|---|---|---|
| 1 | 浏览器打开 `<你的地址>/health` | `{"ok":true,...}` |
| 2 | 卡片上点「检查连接」 | "连接正常，正在收微信消息" |
| 3 | 连接配置里的数据表那一行 | **绿色**「云端数据表已就绪（5 张）」 |
| 4 | 扫码之后卡片 | "这个微信正在扮演「角色名」"+「最近轮询」时间在往前走 |
| 5 | 用那个微信号发一条消息 | 10~60 秒内收到回复（可能分成好几条气泡，正常） |

第 5 步过了，就彻底装好了——之后日常零操作，微信里直接聊就行。

## 六、出问题先看这里

| 现象 | 大概率原因 | 怎么办 |
|---|---|---|
| 卡片点「检查连接」报"连不上" | 地址填错 / 后端没部署成功 | 浏览器打开 `<地址>/health`：打得开说明地址没问题；打不开回 Cloudflare 看 **Deployments** 有没有成功 |
| 数据表那行一直是琥珀色 | 还没建表 | 点 **初始化数据表**；如果按钮点了还是琥珀色，看右上角红字提示 |
| 微信里发消息没人回 | ① 定时器没加 ② 模型凭据没存 ③ 没扫码/绑错角色 | ① 看卡片「最近轮询」时间在不在动，不动就是定时器没生效 → 回 Worker 的 **Settings → Trigger events** 确认 `* * * * *` 那条在；② 连接配置里重新点「保存凭据」；③ 重新扫一次码 |
| 卡片亮黄字「登录会话已过期」 | 微信侧会话过期，或只是瞬时抖动 | **先点「检查连接」**——云端本来每分钟也会自己重试，多数情况会自己恢复；一直不行再重新扫码（旧绑定会自动清理） |
| 部署之后全部报错 / App 显示"没法解密" | `MASTER_KEY` 存成了 **Text** 类型，被下一次部署清掉了 | 回 **Variables and Secrets** 重新加，**类型选 Secret**；如果换过新的密钥串，旧的登录态和凭据解不开，需要重新扫码 + 重新保存凭据 |
| 微信里显示"暂无法连接" | 后端很久没轮询（比如定时器断过） | 等几分钟会自己恢复；**这期间的消息不会补发** |
| 卡片显示"没法解密 token" | `MASTER_KEY` 被换过 | 换回原来那一串；真找不回来就得重新扫码 + 重新保存凭据 |

还搞不定，就把这两样发给帮你装的人：① 浏览器打开 `<你的地址>/wx/status` 看到的整段内容（**注意：这段可能包含你的配置信息，只发给你信任的人**）；② 卡片的截图。

## 七、已知边界（不是 bug，是协议就这样）

- **角色不会主动在微信里找你**：微信的接口要求"回复必须带对方刚发那条消息的凭据"，所以只能被动回复。想让它主动找你，用 App 里的「主动消息 2.0」。
- **只能发文字**：你发图/语音，App 里会显示成占位文字；角色想发表情包也只会被剥掉（不会发图）。
- **回复要等一会儿**：正常 10~60 秒。关掉 App 时最坏可能等 40 秒左右（云端每分钟看一次）+ 生成时间。
- **离线期间的消息不补发**：后端超过一段时间没轮询（比如定时器断了好几天），微信侧会显示"暂无法连接"，这期间对方发的消息收不到。
- **一个微信绑一个角色**：想多个角色同时上微信，就多准备几个小号，各自绑各自的。

## 八、以后想更新后端

后端代码升级时（比如修了 bug）：回到 Cloudflare 的 Worker → **Edit code** → 全选删掉 → 粘进新的 `wechat-bridge-worker.bundle.js` → **Deploy**。

**数据库、密钥、微信登录态都不会动**，不用重新扫码。

## 附录 A · 想用命令行装（wrangler）

适合已经装了 Node.js 和 wrangler 的人：

```bash
# 0) 打包（仓库里已带产物，改过代码才需要重跑）
pnpm build:workers

# 1) 建 D1（把输出的 database_id 填进 worker/wechat-bridge/wrangler.toml）
wrangler d1 create sullyos-wechat-bridge --config worker/wechat-bridge/wrangler.toml

# 2) 建表（也可以在 App 里点「初始化数据表」，二选一）
wrangler d1 execute sullyos-wechat-bridge --config worker/wechat-bridge/wrangler.toml --file=worker/wechat-bridge/schema.sql

# 3) 配密钥
wrangler secret put MASTER_KEY --config worker/wechat-bridge/wrangler.toml      # 随便一串够长的乱码
wrangler secret put WX_BRIDGE_TOKEN --config worker/wechat-bridge/wrangler.toml # 建议配

# 4) 部署
wrangler deploy --config worker/wechat-bridge/wrangler.toml
```

> ⚠️ `--config worker/wechat-bridge/wrangler.toml` 不要省：仓库根目录还有一份 `wrangler.jsonc`，
> 不显式指定配置文件的话命令会打到错的地方去。
